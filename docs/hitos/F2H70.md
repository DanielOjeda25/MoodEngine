# F2H70.1 — Sistema data-driven de vehículos (Source/Valve-style)

**Estado:** Cerrado (2026-05-20)
**Tag:** `v1.58.0-fase2-hito70-1`
**Predecesor:** F2H69 (DeLorean swap parcial, 3 bugs sistémicos diferidos).
**Sucesor planeado:** **F2H70.2** — tuning físico (frame inverso post-reorient, spawn elevation spring-aware, chassis damping).

---

## Motivación

F2H69 dejó el DeLorean integrado en el sample pero con tres workarounds asset-specific en el moodmap (`position.y=0.568`, `rotationEuler=[0,180,0]`) que el dev rechazó por no escalar: *"qué pasa si mañana yo agrego 10 autos más? entiendo que tendremos que tener algo más complejo como un sistema para trabajar otros autos... tener los valores hardcodeados, no lo veo realmente viable."*

El plan inicial de F2H70 era "fix 3 bugs" (spawn-height, quat sync, split-by-node). Mid-sesión el dev objetó al ver que yo proponía hardcodear specs reales del DMC-12 en `makeDefaultSA()`, y pivoteamos a un **sistema data-driven completo** estilo Source/Valve (`scripts/vehicles/<car>.txt`). F2H70 creció a 9 bloques; se subdividió en 3 sub-fases (F2H70.1 / .2 / .3).

---

## Filosofía industrial — Source Engine / Valve

Source Engine ships con `scripts/vehicles/jeep_test.txt`, `airboat.txt`, `jalopy.txt` como referencia. El pipeline (HL2 / Garry's Mod / 200+ mods):

- **1 archivo por vehículo** (`scripts/vehicles/<car>.txt`, formato KeyValues VDF — analogo a JSON).
- **Spec declarativa por axle, no por wheel individual**: la mayoría de los autos son simétricos L/R. Un axle delantero + un trasero, cada uno con `wheel { radius, mass, friction }`, `suspension { springConstant, damping }`, `torque_factor`, `brake_factor`.
- **Bloques semánticos**: `body { massCenter, ... }`, `engine { horsepower, maxRPM, axleratio, gear[N] ratio }`, `steering { degreesSlow, degreesFast }`.
- **Convenciones documentadas** en Valve Developer Wiki ("Vehicle scripting"), reusables para devs viniendo del modding de Source.

Replicamos esa estructura (con JSON en vez de VDF para consistencia con el resto del proyecto y mejor toolchain `nlohmann/json`).

## Bloques

### Bloque A — Auto-spawn-height vía `TransformComponent.pivotYOffset`

Campo runtime-only `f32 pivotYOffset = 0.0f` en TC. `worldMatrix()` aplica `position.y + pivotYOffset` antes del translate. **No se persiste** en el moodmap — se recalcula al cargar / spawn.

- **`VehicleSystem::tick` materialize lazy**: `tf.pivotYOffset = chassisRenderYOffset(e, assets)` que devuelve `-mesh->aabbMin.y` del `MeshAsset`. Patrón Unity/Unreal: el motor auto-eleva el body al AABB del mesh.
- **`SceneLoader::applyOneEntity`**: si entity tiene `VehicleComponent + MeshRendererComponent`, setea el pivotYOffset ahí mismo. Necesario para Editor mode (sin Play, VehicleSystem no corre).
- **`VehicleSystem` post-tick**: `writeWorldMatrixToTransform` recibe el offset y lo RESTA antes de escribir al TC. Así `tf.position` queda en "raw" (lo que el dev escribió en el moodmap) y `worldMatrix()` lo re-aplica transparente al renderear / spawn Jolt. Sin esto, el TC quedaría con el offset bakeado de Jolt → se persistiría mal al guardar y se duplicaría al recargar.
- **Helper público** `Mood::VehicleSystem::chassisRenderYOffset(Entity, AssetManager&)` exportado en `VehicleSystem.h` para reuso (e.g., SceneLoader).

### Bloque B — Quat sync sin gimbal

Campos nuevos en TC: `glm::quat rotation{1.0f, 0.0f, 0.0f, 0.0f}` + `bool useQuaternion = false`. `worldMatrix()` con `useQuaternion=true` aplica `mat4_cast(rotation)` en lugar de euler XYZ.

- **`VehicleSystem::writeWorldMatrixToTransform`**: extrae quat con `glm::quat_cast(mat3(world))` post-step de Jolt. Setea `tf.rotation + tf.useQuaternion=true`. Sin pasar por euler intermedio → resuelve el bug de F2H69 donde rotaciones cercanas a singular configs (180° en Y) producían orientaciones visualmente distintas tras el round-trip euler.
- **`InspectorPanel_Transform`**: si `useQuaternion=true`, refresca `rotationEuler` desde el quat para display consistente. Al editar manualmente los campos euler, resetea `useQuaternion=false` (intención del dev gana sobre cache de quat).

### Bloque C — Schema `.moodvehicle` v2 axle-based

Estructura JSON replicando Source's KeyValues:

```jsonc
{
  "schemaVersion": 2,
  "metadata": { "name": "...", "make": "...", "model": "...", "year": ... },
  "body": {
    "dimensions_mm": [1853, 1136, 4220],   // [W, H, L] full extents
    "mass_kg": 1230,
    "mass_center_override_mm": [0, -100, -400]
  },
  "axle_front": {
    "offset_z_mm": 1205,         // wheelbase/2 hacia adelante
    "track_mm": 1588,            // distancia rueda izq-der
    "attach_y_mm": -300,         // mount del shock sobre chassis local Y
    "wheel": { "radius_mm": 330, "width_mm": 195, "friction_long": 1.4, "friction_lat": 1.3 },
    "suspension": { "frequency_hz": 1.8, "damping": 0.6, "max_length_mm": 300, "min_length_mm": 100 },
    "torque_factor": 0.0,        // RWD → eje delantero NO recibe torque
    "steered": true,
    "handbraked": false
  },
  "axle_rear": { ... torque_factor: 1.0, handbraked: true ... },
  "engine": {
    "horsepower": 130,
    "peak_torque_nm": 208,
    "peak_torque_rpm": 2750,
    "redline_rpm": 5500,
    "idle_rpm": 800,
    "transmission": "5-speed-manual",   // preset, gear_ratios automático
    "final_drive_ratio": 3.444
  },
  "brakes": {
    "deceleration_target_mps2": 7.0,     // dev declara "frenar a X m/s²", no Nm
    "handbrake_ratio": 0.5
  },
  "steering": {
    "max_angle_deg_slow": 32,
    "throttle_steering_rest_rate_slow": 4.0
  }
}
```

**Conversiones internas en `AssetManager_Vehicle::parseVehicleConfigJsonV2`**:

- `dimensions_mm = [W, H, L]` → `chassisHalfExtents = [W/2000, H/2000, L/2000]` (mm → m, full → half).
- `axle_front` → expandido a `WheelFL + WheelFR` con `attachLocal = [-track_mm/2000, attach_y_mm/1000, offset_z_mm/1000]` y mirror para FR.
- `transmission: "5-speed-manual"` carga gear ratios típicos `[3.36, 2.06, 1.38, 1.00, 0.82] + reverse [3.10]`. Presets también para `4-speed-auto` y `6-speed-manual`. Override explícito via `gear_ratios` array gana.
- `brakes.deceleration_target_mps2` deriva `brakeTorque = mass * decel * wheel_radius / 4_wheels` (patrón Source: dev declara "frenar a 7 m/s²", el engine deriva el torque).
- `torque_factor > 0` → `wheel.driven = true`. Sin granularidad (Jolt reparte uniforme entre las driven wheels); diff con `torque_factor` distinto entre axles queda como mejora futura.

`schemaVersion: 2` triggea el nuevo parser. **Dispatcher**: `parseVehicleConfigJson` lee `schemaVersion` (default 1) y delega a `parseVehicleConfigJsonV1` o `parseVehicleConfigJsonV2`. v1 sigue funcionando (forward-compat).

### Bloque D — Convenciones de assets + scripts headless versionados

**`docs/asset_conventions.md`** define la convención canónica del engine:

| campo | valor |
| --- | --- |
| Unidad | 1 unit = 1 metro (Unity/Unreal convention) |
| Up / Forward / Right | +Y / +Z / +X (estándar glTF 2.0) |
| Origin | libre — engine absorbe via `pivotYOffset` |
| Determinante | `det(M) > 0` en todo el grafo (sin mirrors baked) |
| Naming canónico (vehicles) | `chassis`, `wheel_FL/FR/RL/RR`, `interior`, `door_*` |

**`tools/glb/`** versionado en repo con 6 scripts genéricos + README + common.py:

| script | propósito |
| --- | --- |
| `verify.py` | AABB + chequeo de convención (escala, forward, det<0) |
| `diag.py` | dump del árbol de nodos con dets local/world |
| `scale.py` | bake uniform scale a vertex positions + node trans |
| `flatten.py` | bake todas las matrices de node + corrige winding cuando det<0 |
| `center_y.py` | recentra origin al centro vertical del AABB |
| `reorient.py` | rota yaw (default 180°) sobre Y y hornea posiciones + normales |

Pre-F2H70, estos vivían en `c:/tmp/` con paths hardcoded del DeLorean. Promoción a `tools/glb/`: argparse para args, `common.py` compartido (`node_local_matrix`, `read_vec3_array`, `write_vec3_array`, `world_aabb`, `collect_mesh_world_transforms`, `reverse_winding`), `--in-place` opt-in, sin paths hardcoded.

### Bloque E — Catálogo `delorean_dmc12.moodvehicle`

`assets/vehicles/delorean/delorean_dmc12.moodvehicle` con specs reales del DMC-12 stock (1981):

- mass 1230 kg
- dimensions [1853, 1136, 4220] mm (match exacto del AABB del modelo procesado en F2H69)
- engine PRV V6: 130 HP, peak torque 208 Nm @ 2750 rpm, redline 5500
- transmission `5-speed-manual` + reverse 3.10 (preset)
- final drive 3.444
- RWD: `axle_front.torque_factor=0`, `axle_rear.torque_factor=1.0`
- track 1588 mm front + rear (símétrico)
- wheelbase 2410 mm (`offset_z_mm: ±1205`)

Moodmap actualizado: `vehicle.configPath = "vehicles/delorean/delorean_dmc12.moodvehicle"`. Sample valido drop-in: chassis físico Jolt ahora tiene las dimensiones exactas del modelo visual (hitbox encaja perfectamente), wheels físicas alineadas con las visuales del .glb (track 1588mm = ±0.794m desde el centro).

### Bloque G — Rename `makeDefaultSA()` → `makeFallbackGenericSedan()`

47 ocurrencias en 9 archivos. Refleja el rol real: NO es "default del DeLorean", es **fallback genérico cuando un `.moodvehicle` no carga** (path vacío, JSON inválido, etc.). El log path emite warn cuando el fallback se usa — alerta al dev que algo está mal con el config.

Specs reales del DeLorean NO viven en C++; están en `delorean_dmc12.moodvehicle`. Cada vehículo nuevo es 1 archivo JSON + 1 .glb, sin recompilar.

Sentinel `__default_vehicle_sa` → `__fallback_generic_sedan` por coherencia.

### Reorient + workaround moodmap (decisión pragmática)

En validación visual emergió un bug residual: post-reorient (yaw 180° aplicado al .glb), **TODOS los controles del auto quedaron invertidos** (W/A/D al revés). El frame visual rotó pero algo en el code-path (probable: cámara FPS del seat mount asume `-Z forward` mientras Jolt usa `+Z`) sigue con la convención vieja.

**Tradeoff offrecido al dev**: (a) revertir el reorient + dejar `rotationEuler [0, 180, 0]` en el moodmap (asset-specific pero funciona ya), (b) atacar el bug sistémico (más tiempo, F2H70.1 no cierra hoy). Dev eligió (a).

Estado final: `.glb` del DeLorean revertido al original (modelo mira -Z localmente). Moodmap usa `rotationEuler: [0, 180, 0]` para que el chassis Jolt + cámara mount queden alineados visualmente. Controles W/A/D funcionan normales. Bug sistémico agendado para F2H70.2.

### Issues pendientes a F2H70.2

1. **Frame inverso post-reorient**: revertir el workaround del moodmap requiere fix en cámara FPS del seat mount (o en `PhysicsWorld_Vehicle.cpp::createVehicle` para alinear forward) que no asuma `-Z forward` del modelo.
2. **Spawn elevation considerar spring rest**: el chassis flota 7-10 cm sobre el piso por el settle natural del spring Jolt al spawn. Fix: `pivotYOffset = wheel_radius + spring_rest_length - aabbMin.y` (no solo `-aabbMin.y`).
3. **Chassis damping ausente**: el auto sigue con momentum indefinido sin acelerador. Exponer `chassis.linear_damping` y `chassis.angular_damping` al schema v2 y propagar a `JPH::BodyCreationSettings`.

Mapa demo: extendido a un camino largo 60m × 8m wide con NPC a 45m del spawn del DeLorean (estructura: Floor + BordeIzq + BordeDer + DeLorean + NPC).

## Decisiones meta

1. **Pivot mid-hito de "fix 3 bugs" → "sistema data-driven completo"**: el dev objetó hardcodear specs por escalabilidad (10+ vehículos futuros). Pivotada eleva el scope pero alinea con engineering profesional. Cost: F2H70.1 deja issues físicos sin resolver (F2H70.2).
2. **Schema v2 paralelo a v1 (no replace)**: forward-compat preservada. Devs que vienen de v1 (`Banshee_SA.moodvehicle` formato antiguo) no se rompen. Si v1 deja de usarse, deprecar en F2H7X+.
3. **Workaround moodmap del DeLorean justificado**: el bug del frame inverso es engineering legítimo a resolver, pero su fix no es scope de "schema parsing". Dev prefirió cerrar F2H70.1 con catalog funcional + bug agendado vs perfeccionarlo en una sesión.
4. **`tools/glb/` versionado en repo, no en `c:/tmp/`**: scripts forman parte del pipeline asset oficial, no son scratch del dev. Argparse + common.py + README + sin paths hardcoded → reusables para vehículos futuros.

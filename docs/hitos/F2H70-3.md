# F2H70.3 — Vehicle Browser + drag-and-drop de vehículos al viewport

**Estado:** Cerrado (2026-05-20)
**Tag:** `v1.60.0-fase2-hito70-3`
**Predecesor:** F2H70.2 (tuning físico: damping + spawn elevation + frame consistente).
**Sucesor planeado:** **F2H70.4** (o cuando se retome) — split-by-node de wheels (rotación visual) + pipeline de packs multi-auto (split + rescale headless).

---

## Motivación

F2H70.1/.2 dejaron el sistema data-driven `.moodvehicle` funcionando, pero la única forma de instanciar un auto era editarlo a mano en el `.moodmap` (entity con `mesh_renderer` + `vehicle` por separado). F2H70.3 cierra el loop de autoría: el `.moodvehicle` se vuelve **self-contained** (declara su propio mesh) y se puede **arrastrar desde el Asset Browser al viewport** para spawnear un auto completo y conducible, igual que mesh/prefab/script/item.

---

## Bloques

### Bloque F — Vehicle Browser tab + drag-and-drop

**Tab "Vehiculos" en el Asset Browser** (`AssetBrowserPanel`):
- `VehicleEntry` struct + scan recursivo de `assets/vehicles/**/*.moodvehicle`. La metadata legible (`metadata.name`, `body.mass_kg`, `engine.horsepower`) se parsea del JSON al escanear para mostrar nombres + `[kg, HP]`. El `id` carga el config via `AssetManager::loadVehicleConfig` para validar que parsea.
- Drag-source emite payload `MOOD_VEHICLE_ASSET` con el path lógico (buffer fijo 256 bytes null-terminated, mismo formato que `MOOD_SCRIPT_ASSET`).
- Icono `ICON_FA_GAUGE` (no existe `ICON_FA_CAR` en el set FontAwesome embebido).

**Drag-and-drop al viewport** (patrón consistente con mesh/prefab/script/item):
- `ViewportPanel`: acepta `MOOD_VEHICLE_ASSET` → `m_pendingVehicleDrop{ndcX, ndcY, path}`. `AssetDragKind::Vehicle` agregado al enum del highlight.
- `EditorApplication::processViewportVehicleDrop()` (en `DemoSpawners_Drop.cpp`): `pickTile` bajo el cursor → crea entity con `TransformComponent` (centro del tile, y=0) + `MeshRendererComponent` (mesh tomado de `VehicleConfig.meshPath`) + `VehicleComponent(configPath, dirty=true)`. Registra undo con `pushCreatedEntities`.

**`.moodvehicle` self-contained** (estilo Source: el script del vehículo referencia su modelo):
- `VehicleConfig.meshPath` (de `body.mesh_path`) — el mesh visual vive en el config, no hay que cablear `mesh_renderer` aparte. DeLorean declara `mesh_path: "vehicles/delorean/delorean.glb"`.
- `VehicleConfig.displayName` (de `metadata.name`) — nombre legible usado como tag del entity al spawnear. Sin esto el tag era el filename stem (`delorean_dmc12`), feo en el prompt "[F] Subir al <tag>".

**Drop dedicado en el Inspector** (vía secundaria — reasignar config a un vehículo existente):
- Un `InputText` no funciona como `BeginDragDropTarget` en ImGui (es un widget activo que consume el drag internamente). Se usa un **botón dedicado** "Soltar .moodvehicle aquí" como zona de drop, mismo patrón que `InspectorPanel_Animation`. Al soltar, asigna el path al `configPath` + marca `dirty` para rematerializar.

**Grounding del spawn**: el drop replica lo que hace `SceneLoader::applyOneEntity` — setea `tf.pivotYOffset = VehicleSystem::chassisRenderYOffset(e, assets)` (chassis half-height + spring rest) + `tf.pivotYawOffsetDeg = cfg.meshYawOffsetDeg`. Sin esto el auto spawneaba atravesando el piso en Editor mode (su origin está en el centro vertical).

---

## Decisiones técnicas

1. **Mesh declarado en el `.moodvehicle` (`body.mesh_path`) en lugar de mesh aparte al spawnear**: hace al config self-contained — arrastrar un solo `.moodvehicle` basta para tener un auto andando. Estilo Source (el `.txt` del vehículo referencia su `.mdl`). El dev eligió esta opción explícitamente sobre "asignar el mesh por separado".

2. **Drop al viewport (no al Inspector) como flujo primario**: el dev señaló que el patrón natural es soltar en el viewport (como mesh/prefab/script), no en un campo del Inspector. El drop del Inspector queda como vía secundaria para reasignar config a un vehículo ya existente.

3. **Botón dedicado como drop-target en el Inspector**: `ImGui::BeginDragDropTarget()` sobre un `InputText` no dispara (el widget consume el drag). Patrón ya validado en el repo (`InspectorPanel_Animation` usa un botón). Evita pelear con el InputText.

## Comportamiento esperado (no-bugs aclarados en validación)

- **Colisión solo en Play mode**: la física de vehículos (constraint Jolt + colisión) solo se materializa/simula en Play mode (`EditorScene.cpp`: el engine solo hace `physicsWorld->step()` en Play). En Editor mode el auto es estático. **F1** solo togglea el debug-draw de AABBs — no habilita colisión.
- **Tag de copias viejas**: entities spawneados antes de este hito (con el prefijo `Vehicle_` que tenía el código intermedio) que hayan quedado **guardados** en un `.moodmap` conservan ese tag. Drops nuevos usan `metadata.name` (ej. "DeLorean DMC-12").

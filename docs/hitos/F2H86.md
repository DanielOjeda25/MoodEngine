## Qué siente el usuario

- En el modal **+ Crear Entidad** → tab **Luces**: ahora hay 3 cards
  (Direccional / Puntual / **Environment**). El botón Environment queda
  **disabled** si la escena ya tiene uno (unicidad por escena, igual que el
  SceneRenderer).
- Click en Environment → spawnea entidad sin mesh placeholder, solo
  `Tag + Transform + EnvironmentComponent`. En el Hierarchy aparece con
  ícono globo (`ICON_FA_GLOBE`) — convención Unity Render Settings /
  Unreal PostProcessVolume / Godot WorldEnvironment.
- En el **Inspector** del Environment, sección "Niebla" → arriba de los
  campos de fog hay un **dropdown "skybox"** con 2 presets shipados
  ("Kloofendal (exterior brillante)" / "Día sintético") + "Personalizado..."
  (file picker). Al cambiar la opción → el cielo del viewport y los
  reflejos IBL hacen swap en el siguiente frame.
- Hint debajo del dropdown: *"IBL bakeado offline con: python
  tools/bake_ibl.py <path>"* — escape hatch claro si el usuario carga un
  HDRI custom sin IBL pre-bakeado.

## Bloques

### A — `ProjectAction::AddEnvironment` + `EditorApplication::handleAddEnvironment`

Gemelo de `handleAddPointLight` / `handleAddDirectionalLight` de F2H60 iter2.
Spawnea `uniqueEntityName(*m_scene, "Environment")` con
`Tag + Transform + EnvironmentComponent` (defaults). **Guard de unicidad**:
si ya existe un Environment en la escena, log info + no-op (mismo criterio
que `SceneRenderer::applyEnvironmentFromScene` que solo procesa el primero).

Hookup:
- `EditorMode.h`: enum `AddEnvironment`.
- `EditorApplication.h`: declaración del handler.
- `EditorApplication_Run.cpp`: case en el dispatcher.
- `EditorProjectActions_CreateEntity_PickModal.cpp`: card nueva en el array
  `kLights[]` (tab "Luces") con flag `disabled = hasEnvironment` precomputado
  fuera del loop (porque `m_scene->forEach` no es invocable dentro del
  contexto del loop sin re-tipar).

### B — `IconHelpers.h`: `EnvironmentComponent → ICON_FA_GLOBE`

Branch nuevo en `iconForEntity(Entity)` con **prioridad alta** (antes de
MeshRenderer) — defensivo: si una entidad migrada tiene ambos (legacy con
placeholder cubo + Environment), el rol semántico es "Environment global",
no "geometría". `ICON_FA_GLOBE` (codepoint `0xF0AC`, UTF-8 `\xef\x82\xac`)
agregado al subset curado en `IconsFontAwesome6.h`.

### C — Generación de `assets/skyboxes/sky_day/` (6 PNGs)

`tools/gen_sky_cubemap.py` ya existía pero la carpeta `sky_day/` no estaba
en el filesystem (sí el IBL bakeado en `assets/ibl/sky_day/`). Run del
script genera los 6 PNGs (px/nx/py/ny/pz/nz) de gradient sintético con
acento sunset en `+Z`. **El IBL ya estaba bakeado de un dump previo** —
no se re-bakeó.

### D — Refactor `SceneRenderer`: `loadSkyboxAndIblFromBase(const std::string&)`

Pre-F2H86, el ctor del `SceneRenderer` cargaba **hardcoded**
`"assets/skyboxes/sky_kloofendal.png"` (equirect) + `"assets/ibl/sky_kloofendal"`
(IBL bake). `EnvironmentComponent::skyboxPath` estaba serializado **pero
nunca consumido** por el render — el campo era placebo.

Refactor:
1. Extracción del código a `loadSkyboxAndIblFromBase(skyboxBase)` — método
   privado de `SceneRenderer`.
2. Auto-detect del modo:
   - `assets/<base>.png` existe → equirect (`SkyboxRenderer::Equirect{}`).
   - `assets/<base>/px.png` existe → cubemap dir
     (`SkyboxRenderer(cubemapDir)`).
   - Ninguno → log warn + skip swap (deja el skybox previo intacto).
3. IBL: deriva `stem = path(base).stem()` → busca
   `assets/ibl/<stem>/{irradiance, prefilter}/`. Si no existe → log warn +
   `m_iblIrradiance/Prefilter.reset()` (el shader cae a `uAmbient` escalar).
4. **BRDF LUT global** (`assets/ibl/brdf_lut.png`) se carga **una vez** en
   el init, no por skybox — es lookup tabular idéntico para todos.
5. **Idempotente**: cache `m_currentSkyboxBase`; `base == cache` → early-out
   (llamar cada frame desde `applyEnvironmentFromScene` es OK).

`init()` ahora llama `loadSkyboxAndIblFromBase("skyboxes/sky_kloofendal")`
como bootstrap (mismo default que antes).

### E — Cableado en `applyEnvironmentFromScene`

Dentro del lambda que itera `EnvironmentComponent`s, capturar `env.skyboxPath`
a una variable local. Después del lambda, si `envFound && !envSkyboxPath.empty()` →
`loadSkyboxAndIblFromBase(envSkyboxPath)`. El loader hace su propio early-out
si no hay cambio. **El swap del skybox ocurre antes del primer draw del
frame** (applyEnvironmentFromScene es llamado por el caller pre-render).

### F — Dropdown UI en `InspectorPanel_Environment.cpp` sección "Niebla"

Reemplazo del `TextDisabled` placebo que decía `"Skybox: {path} (asset
catalog futuro)"` por un `BeginCombo` con 2 presets + "Personalizado...".
Patrón clon del Color Grading LUT dropdown de F2H58 Bloque H:
- Tabla const de presets `{labelKey, path}`.
- Preview computado runtime (preset label o "Personalizado: <filename>").
- Item separator + "Personalizado..." dispara `pfd::open_file` filtrado a
  `*.png`, root en `assets/skyboxes/`. Path resuelto a relativo a
  `assets/` si está dentro, absoluto si fuera (escape hatch).

Hint debajo del combo (TextDisabled): instrucciones del bake offline.

### G — Default del componente actualizado

`EnvironmentComponent::skyboxPath` por defecto era `"skyboxes/sky_day"`.
Cambio a `"skyboxes/sky_kloofendal"` para alinearlo con el bootstrap del
SceneRenderer. **Implicación**: las entidades nuevas creadas via `+ Crear
Entidad > Environment` quedan con kloofendal (no disparan swap involuntario
al cargar). Test nuevo guarda la regresión.

## Decisiones

### D1 — F2H86 grande (1.0 + HDRI real) en vez de hito chico (solo 1.0)

**Contexto:** Inicialmente propuse cerrar F2H86 como **solo 1.0** (entry
point + ícono + guard) y diferir el HDRI switcher a F2H87 propio porque
descubrí que la estimación del BACKLOG (2-3h reusando Color Grading LUT
pattern) subestimaba el scope — el `skyboxPath` no estaba cableado al
renderer (placebo) y el bake IBL no es texture upload trivial.

**Decisión del dev:** *"1.0 + HDRI real (6-8h)"*. Cerrarlos juntos porque
están en el mismo subsistema (`EnvironmentComponent`).

**Razones:**
- Evita dos pasadas al `InspectorPanel_Environment.cpp` + `SceneRenderer`.
- El refactor de `loadSkyboxAndIblFromBase` queda como infra reusable
  para cualquier futuro feature de IBL dinámico.
- Si se hubiera dejado solo 1.0, la UX quedaba mocha (Environment como
  entidad pero sin poder cambiar el skybox = motivo de fricción persistente).

### D2 — Auto-detect equirect vs cubemap dir en el loader

**Contexto:** Hay 2 formatos coexistiendo:
- Kloofendal: equirect PNG único (`assets/skyboxes/sky_kloofendal.png`).
- Day sky: cubemap dir 6 PNGs (`assets/skyboxes/sky_day/{px,nx,py,ny,pz,nz}.png`).

**Decisión:** `loadSkyboxAndIblFromBase(base)` chequea `<base>.png` primero
(equirect), si no `<base>/px.png` (cubemap dir). El usuario no se entera
del formato — solo elige preset.

**Razones:**
- Compatibilidad histórica (Hito 15 ya soportaba ambos modos en
  `SkyboxRenderer`).
- HDRIs de Polyhaven vienen como equirect; cubemaps procedurales son dir.
- Una única convención de path mata el otro formato — perderíamos assets
  ya generados.

### D3 — BRDF LUT separado del swap

**Contexto:** El IBL completo son 3 cubemaps + 1 LUT: irradiance,
prefilter (5 mips), brdf_lut. El BRDF LUT es **tabular** (no depende del
environment — es función de `(N·V, roughness)` precomputada).

**Decisión:** Cargar BRDF LUT **una vez en el init**, no por skybox.
`loadSkyboxAndIblFromBase` solo toca irradiance + prefilter.

**Razones:**
- BRDF LUT no cambia con el HDRI → recargarlo es waste.
- Reduce GL state churn per-swap (1 texture upload menos).
- Mismo patrón que Unity / Unreal (BRDF LUT es global del engine, no
  per-volume).

### D4 — File picker "Personalizado..." sin auto-bake del IBL

**Contexto:** El user puede elegir un HDRI custom via file picker. Bakear
el IBL **en runtime** requiere compute shaders (importance sampling +
prefilter convolution) — 4-6h de implementación adicional.

**Decisión:** Aceptar el path, log warn si el IBL bake no existe, hint en
el Inspector explicando el workflow offline (`python tools/bake_ibl.py
<path>` + reload). El skybox visualmente cambia; los reflejos IBL caen a
ambient escalar hasta que se bakee.

**Razones:**
- Workflow industrial: Unity y Unreal también bakean IBL offline (el
  "Reflection Probe" se bakea on-demand, no por frame).
- Runtime bake = scope F2 o F3 (compute shaders ya están en el roadmap).
- El bake offline ya existe (`tools/bake_ibl.py`) y es razonable
  (~30s/HDRI).

### D5 — Cambio del default `skyboxPath` a `sky_kloofendal`

**Contexto:** Pre-F2H86 el componente decía `"skyboxes/sky_day"` pero el
renderer cargaba `kloofendal` hardcoded — mismatch silencioso. Post-F2H86
el path se respeta runtime → si dejaba sky_day como default, **todo
Environment recién creado pediría swap a sky_day** al cargar.

**Decisión:** Cambiar default del struct a `"skyboxes/sky_kloofendal"`.
Test nuevo guarda la regresión.

**Razones:**
- Coherencia: el bootstrap del renderer también es kloofendal.
- `.moodmap` antiguos que tienen `sky_day` explícito siguen funcionando
  (el `parseEntityFromJson` respeta el valor del JSON, default solo se
  usa si la key está ausente).
- Tests existentes (`test_scene_serializer`, `test_package_builder`)
  setean valores explícitos — no afectados.

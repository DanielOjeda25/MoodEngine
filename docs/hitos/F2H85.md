# F2H85 — Save As contextual + Shift+D duplicate

**Estado:** Cerrado (2026-05-23)
**Tag:** `v1.76.0-fase2-hito85`
**Predecesor:** F2H84 (Undo unificado en asset editors).
**Sucesor planeado:** sin item específico del plan original — atajos
configurables (F2H42 original) sigue diferido por decisión del dev.

Décimo hito de **Sub-fase 2.7**. Dos quality-of-life chicos que cerraron
items históricos del BACKLOG:

- **Ctrl+Shift+S contextual** (`docs/BACKLOG.md` § "menores 2.7"): el
  Ctrl+S contextual de F2H78 ya respetaba el foco; este hito agrega su
  hermano "Guardar como" — guarda el editor enfocado en una ruta nueva
  con su extensión nativa, o el proyecto entero como fallback.
- **Shift+D duplicate** (`docs/BACKLOG.md` § 1.-3): pedido tuyo en
  F2H64, hoy entregado.

---

## Qué siente el usuario

- **Ctrl+Shift+S** en el viewport → diálogo "Guardar proyecto como"
  (ya existía como `handleSaveAs`, ahora hay shortcut).
- **Ctrl+Shift+S** con el Item Property Editor enfocado → diálogo
  "Guardar item como" filtrado a `.mooditem`, default
  `<stem>_copy.mooditem`. Tras guardar, el panel queda apuntando al
  archivo nuevo (browser refrescado).
- **Ctrl+Shift+S** con el Quest Property Editor enfocado → idem con
  `.mooquest`.
- **Shift+D** con una o varias entidades seleccionadas → cada una se
  duplica con offset +0.5 m en X y tag `<original>_copy`. La copia
  queda seleccionada (multi: la última como active). Ctrl+Z deshace
  toda la duplicación de un golpe.

## Bloques

### A — `IPanel::consumesSaveAsShortcut()` virtual

Gemelo del `consumesSaveShortcut()` de F2H78. Default `false`; los
editors guardables lo override cuando tengan foco y haya algo cargado.

### B — Handler global Ctrl+Shift+S en `EditorApplication::processEvents`

Gemelo del handler Ctrl+S existente. Discrimina por
`KMOD_SHIFT` en el modifier para no doble-disparar con Ctrl+S puro
(el handler de Ctrl+S original ahora exige `!(mod & KMOD_SHIFT)`).
Si algún panel visible consume el atajo, no se dispara
`ProjectAction::SaveAs` global.

### C — `saveAsToDisk()` en Item + Quest editors

Mismo template:
1. `pfd::save_file` con default `<stem>_copy.<ext>` en la carpeta del
   asset original.
2. Forzar extensión nativa si el usuario no la escribió.
3. `m_loaded.saveToFile(outPath)`.
4. Switch del panel al path nuevo (`m_loadedPath = outPath`).
5. `historyStack->clear()` — los lambdas de F2H84 capturan
   `this->m_loaded`; el path cambió y los comandos previos quedan
   obsoletos. Mismo razonamiento que `loadFromPath`.
6. Refresh del browser correspondiente.

i18n: 2 keys nuevas (`item_editor.save_as`, `quest_editor.save_as`)
en/es.

**Hotkey local en `drawSaveBar`**: cada panel detecta Ctrl+Shift+S
con `ImGui::GetIO().KeyCtrl && KeyShift && IsKeyPressed(S)`. Lo
distingue de Ctrl+S puro con `!KeyShift`.

**No entra**: Material editor (el path lo administra el AssetManager,
no el panel; necesita un `saveMaterialAs(id, newPath)` que es scope
distinto). Script + Shader editors (afectan `ScriptComponent.path`
de una entity, side-effects en el componente). Diferidos.

### D — `EditorApplication::duplicateSelectedEntities()`

Implementado en `EditorScene.cpp`. Pseudocódigo:

```cpp
for (Entity src : sel.selected) {
    if (tagOf(src) starts with "Tile_") continue;  // GridMap, no se duplica
    auto json = serializeEntityToJson(src, *m_assetManager);
    SavedEntity saved = parseEntityFromJson(json);
    saved.position += vec3(0.5f, 0, 0);
    saved.tag += "_copy";
    Entity dup = SceneLoader::applyOneEntity(saved, *m_scene, *m_assetManager, true);
    created.push_back(dup);
}
pushCreatedEntities(created, "Duplicar entidad");  // undoable + markDirty
clear(sel); for (e : created) add(sel, e);  // select copies
```

`serializeEntityToJson` + `parseEntityFromJson` + `applyOneEntity` son
infra preexistente (Hito 27 `DeleteEntityCommand` los usa también). El
hito aporta el wiring, no infra nueva.

### E — Handler Shift+D en `processEvents`

Gate: solo Editor Mode, `KMOD_SHIFT` activo, `!KMOD_CTRL` (Ctrl+D
reservado a otros usos), `!KMOD_ALT`, `!WantTextInput` (no robar la
'D' a un campo de texto).

## Decisiones

### D1 — Save As contextual con el mismo patrón de F2H78, no comando global único

**Contexto:** Una alternativa era centralizar Save As en `EditorApplication` con un dispatcher (`saveAsFromShortcut()`) que pregunte a cada panel.

**Decisión:** Mantener el patrón de F2H78 (cada editor maneja su Ctrl+Shift+S en su render; el handler global solo gatea el project-saveAs). Mismas razones que F2H78: menos invasivo, idiomático ImGui (foco se consulta dentro del render), respeta el `m_windowFocused` que ya existe.

### D2 — Diferir Material / Script / Shader Save As

**Contexto:** El hito original quería los 5 editors guardables. Material es complejo (saveMaterial usa el path interno del AssetManager); Script + Shader afectan un componente de una entity (side-effect, no es un asset standalone).

**Decisión:** Solo Item + Quest (cuyo `saveToFile` ya toma un path arbitrario). Documentar en BACKLOG el resto.

**Razones:** Item/Quest cubren el caso 80%. Atacar Material/Script/Shader requiere refactor del AssetManager (saveMaterialAs(id, newPath)) o de ScriptComponent (update path with side-effect), scope que no justifica este hito.

### D3 — Offset Shift+D fijo en +X vs cursor-relative

**Contexto:** Blender usa offset basado en mouse (la copia "sigue" al cursor hasta confirmar con click). Implementar eso en Mood requiere modal state + cursor tracking + Enter/Esc handlers.

**Decisión:** Offset fijo `(+0.5 m, 0, 0)` por simplicidad. El usuario mueve la copia con el gizmo / G shortcut después.

**Razones:**
- Pedido del backlog era "Shift+D duplicate" sin mencionar modal mouse-tracked.
- 0.5 m es suficiente para distinguir visualmente la copia del original.
- Si emerge fricción, F2 puede agregar modo mouse-tracked.

### D4 — Skip tiles del GridMap silenciosamente

**Contexto:** Una entity con tag `Tile_X_Y` es el render de una celda de `m_map`. Duplicarla crea una entity huérfana fuera del grid; al rebuild de `m_scene` desde `m_map`, desaparece.

**Decisión:** Skip silencioso (sin log warning). Si la selección era 100% tiles, `duplicateSelectedEntities` es no-op.

**Razones:** El usuario que selecciona un tile probablemente quería editar el grid, no clonar una geometría. Mismo razonamiento que `deleteSelectedEntity` (que también trata tiles como un caso especial → `SetTileCommand` "Vaciar tile" en vez de delete).

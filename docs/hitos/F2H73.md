# F2H73 — Triggers avanzados (filtro por tag + one-shot + enabled)

**Estado:** Cerrado (2026-05-21)
**Tag:** `v1.64.0-fase2-hito73`
**Predecesor:** F2H72 (Force fields / zonas de fuerza física).
**Sucesor planeado:** resto de Sub-fase 2.4 (cloth / soft body) o el gestor de vehículos (backlog).

---

## Motivación

El `TriggerComponent` (Hito 33 + 37 + 39/40) detectaba al player y a los bodies que entraban/salían de su volumen y despachaba eventos de script (`on_trigger_enter`, `on_trigger_body_enter`, etc.), pero **siempre disparaba con cualquier cosa**. Faltaban los filtros y modos que cualquier engine da en sus volúmenes de trigger:

- **Filtrar por qué entra** (un kill-volume que solo mata enemigos, una puerta que solo abre con el player).
- **Disparar una sola vez** (un checkpoint, un cinematic-trigger que no debe repetirse).
- **Apagar el volumen** sin borrarlo (togglear una zona desde un script).

Referencia industrial: Unreal `TriggerVolume` + `ActorHasTag` / clases permitidas; Unity `OnTriggerEnter` + tag check + `enabled`; los `trigger_once` / `filter_activator_name` de Source. No reinventa nada: son flags sobre el `TriggerSystem` que ya existía.

---

## Bloques

### Triggers avanzados end-to-end

- **`TriggerComponent`** (Components.h) — campos nuevos:
  - `requiredTag` (string, vacío = cualquier body): solo los bodies cuyo `TagComponent.name` coincide cuentan para el trigger. No afecta al player.
  - `triggersOnPlayer` (bool, default `true`): si `false`, ignora al player char y solo reacciona a bodies físicos.
  - `oneShot` (bool, default `false`): dispara una vez y queda "muerto" hasta recargar el mapa.
  - `enabled` (bool, default `true`): master switch; `false` = no despacha nada.
  - **Estado runtime (no serializado)**: `fired` (one-shot ya disparado), además del `playerInside` / `bodiesInside` existentes.
- **`TriggerSystem`** (`src/systems/physics/TriggerSystem.cpp`):
  - Gate al tope del lambda: `if (!enabled) return;` y `if (oneShot && fired) return;`.
  - Player: gated por `triggersOnPlayer` (si está off, fuerza `playerInside=false` sin disparar exit).
  - Bodies: el pre-collect ahora guarda el `tag` de cada body (`BodyEntry { entityRaw, position, tag }`); en el loop, `if (!requiredTag.empty() && be.tag != requiredTag) continue;` filtra los que no matchean.
  - `oneShot` se arma en el **primer enter** (player o body): setea `fired = true` y corta el procesamiento del frame.
- **Editor**: sección de Inspector ampliada — `InputText` para `requiredTag` (con help marker) + 3 checkboxes (`triggers_on_player` / `one_shot` / `enabled`) + texto "(one-shot ya disparó)" cuando `fired`. Claves i18n nuevas en `en.json` / `es.json`.
- **Serialización** round-trip aditiva (`EntitySerializer` + `SavedTrigger` + `SceneLoader`): los 4 campos se escriben **solo si difieren del default** (JSON limpio + back-compat: mapas viejos cargan igual). Se agregó `TriggerComponent` al **gate del `SceneSerializer`** — un trigger es una entity **standalone** (sin mesh), igual que `InventoryComponent` y `ForceFieldComponent`; sin esto, un trigger suelto no se persistía.
- **Demo** `assets/maps/physics_triggers_demo.moodmap`: una `ZonaTrigger` apoyada en el piso con `required_tag = "VIP"`, una caja tag `VIP` (dispara) y una caja tag `Comun` (filtrada).

## Decisiones técnicas

1. **`requiredTag` filtra solo bodies, no al player**: el player tiene su propio gate (`triggersOnPlayer`). Mezclarlos (exigirle un tag al player) no tiene caso de uso real — el player es único, se togglea con un bool, no se filtra por tag.

2. **`oneShot` se arma al primer enter de cualquier fuente**: si el player o un body válido entra, el trigger queda muerto. No se distingue "one-shot solo para player" vs "solo para body" — `triggersOnPlayer` + `requiredTag` ya acotan qué puede armarlo.

3. **Campos avanzados se serializan solo si != default**: mapas creados antes de F2H73 no traen las claves y cargan con los defaults correctos (`required_tag=""`, `triggers_on_player=true`, `one_shot=false`, `enabled=true`). Forward/backward compatible sin bump de versión.

4. **`fired` es runtime, no se persiste**: recargar el mapa resetea el one-shot (un checkpoint vuelve a estar "armado" al reabrir). Igual que `playerInside` / `bodiesInside`.

---

## Comportamiento esperado

- Los eventos de script (`on_trigger_enter` / `_exit` / `_body_enter` / `_body_exit` / `_stay`) no cambian; los flags solo deciden **si** se despachan.
- `enabled=false`: el trigger no despacha nada aunque un body válido caiga adentro (la física sigue: los bodies son dynamic y caen por gravedad, simplemente el trigger los ignora).
- El overlay (`F1`) dibuja el OBB del trigger en verde igual que antes, independiente de los flags.

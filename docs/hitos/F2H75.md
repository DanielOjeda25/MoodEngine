## Qué siente el jugador

Banderas, estandartes y cortinas que **cuelgan por gravedad y flamean con el
viento**. La tela se ancla por un borde (asta/barra) y el resto se mueve solo;
una **zona de viento** (`ForceFieldComponent`, F2H72) la hace ondear. Se ve
como tela real: superficie sólida iluminada, visible de los dos lados.

**Fuera de scope (acordado):** la tela NO choca con objetos (solo gravedad +
viento + anclajes), no hay soft bodies volumétricos (jelly/globos), no se rasga,
y se crea como **grilla procedural** NxM (no se importa desde `.glb`).

## Bloques

### A — `ClothLayout` (header puro, sin Jolt)
`src/engine/physics/cloth/ClothLayout.{h,cpp}`. Genera la grilla mass-spring:
partículas en el plano XY local (fila 0 = borde superior, para que cuelgue bajo
−Y) + resortes en 3 familias (**structural** vecinos directos, **shear**
diagonales, **bend** vecinos a 2) + índices de triángulos (2 por celda). El
`AnchorEdge` (None/TopEdge/TopCorners/LeftEdge) marca qué partículas quedan
fijas. Testeable headless.

### B — `PhysicsWorld_SoftBody.cpp` (wrapper Jolt v5.2.0)
`createCloth` arma `JPH::SoftBodySharedSettings` (vertices con invMass 0 en las
ancladas + edges con compliance derivada de stiffness + faces de los triángulos)
y crea el `SoftBody` (`CreateAndAddSoftBody`). `destroyCloth`,
`readClothVertices` (posiciones world, vía `body.GetCenterOfMassTransform() *
vertex.mPosition`) y `applyClothAcceleration` (suma a la velocidad de las
partículas no ancladas — Jolt solo permite mutar invMass/velocity en runtime).
`mUpdatePosition=false` (la tela está clavada, su COM no se traslada).

### C — `ClothComponent` + serialización
Params serializados (width/height/resX/resY/anchor/totalMass/stiffness/damping/
useGravity/color) + runtime (clothId, dirty, renderVertices). Round-trip aditivo
(`EntitySerializer` + `SavedCloth` + `SceneLoader`) + gate del `SceneSerializer`
(la tela es una entity standalone sin mesh).

### E — Mesh dinámico (la infra nueva)
Hasta F2H74 toda la geometría era estática (`GL_STATIC_DRAW`) o skinneada. La
tela necesita un mesh cuyos **vértices se reescriben cada frame**. `OpenGLCloth-
Renderer` (espejo de `OpenGLParticleRenderer`): VBO `GL_DYNAMIC_DRAW` re-subido
por tela con orphan + `glBufferSubData`. Shader `cloth.{vert,frag}` lit simple
(1 direccional + ambiente), **doble cara** (`gl_FrontFacing` invierte la normal;
`GL_CULL_FACE` off en el scope del draw). Invocado por `SceneRenderer` junto al
particle renderer (post-opaco), con la luz direccional del frame (fill default
si no hay sun).

### D — `ClothSystem` (`src/systems/physics/`)
`tick` (Play): materializa lazy (`dirty → createCloth`), re-materializa si el dev
edita params, y cada frame lee las posiciones del soft body → recalcula normales
suaves → escribe el buffer interleaved (`renderVertices`). `previewRest` (editor
sin Play): produce el buffer desde la pose plana analítica (sin física) para ver
la tela en el viewport. Layout cacheado por entity (rebuild solo si cambian los
params geométricos). `enterPlayMode` resetea las telas (sim fresca cada Play).

### F — Editor
*Add Component → Física → Tela*; sección de Inspector (dimensiones, resolución
2–40, anclaje, masa, rigidez, amortiguación, gravedad, color) con i18n en/es.
Editar params de sim marca `dirty` (re-materializa); el color es live.

### G — Viento + demo
`ForceFieldSystem` extendido: las zonas afectan también a las telas (recolecta
soft bodies, aplica `applyClothAcceleration` a las que caen dentro; la magnitud
se trata siempre como aceleración). Demo `assets/maps/cloth_demo.moodmap`: una
bandera roja anclada por el borde izquierdo + un WindZone direccional (+Z).

## Decisiones técnicas

1. **Grilla procedural, no import de mesh**: una tela es un caso de geometría
   regular; generarla NxM desde params evita un pipeline "mesh → soft body"
   (mapear vértices arbitrarios a constraints) que es un hito propio. El dev
   elige ancho/alto/resolución/anclaje.

2. **Mesh dinámico en renderer dedicado (no MeshRendererComponent)**: el path
   de mesh estándar asume geometría estática + asset cacheado + `uModel`. La
   tela tiene vértices world-space que cambian por frame. Un renderer dedicado
   (como partículas) evita perturbar el pipeline de assets/materiales y mantiene
   el blast radius chico. Costo: shader lit propio (direccional + ambiente) en
   vez de PBR completo — suficiente para una bandera; upgradeable a futuro.

3. **Doble cara vía `gl_FrontFacing`** en vez de duplicar triángulos: las telas
   se ven de ambos lados; invertir la normal en el back-face da lighting
   coherente sin duplicar geometría ni VBO.

4. **`stiffness [0,1] → compliance`**: el dev piensa en "rigidez" (1 = firme),
   no en compliance de Jolt (inverso, m/N). Mapeo `(1−stiffness)·1e-3`.

5. **Viento = aceleración para la tela**: las partículas de un soft body no
   exponen masa uniforme; tratar la magnitud del Force Field como aceleración
   (integrada por dt sobre la velocidad) da un flameo consistente.

6. **`previewRest` analítico en editor**: sin step de física, la tela se vería
   colapsada. La pose plana analítica (layout × Transform) la muestra correcta
   en el viewport sin simular — mismo criterio que `VehicleSystem::previewRest`.

## Fix lateral (reactivo, ajeno al cloth)

**Crash del Slider constraint con `min == max`**: Jolt v5.2.0 hace assert
(`SliderConstraint.cpp:159`, "Better use a fixed constraint") cuando los límites
son iguales, crasheando en Debug. Un slider con travel cero ("bloqueado" desde
el editor) es UX válida → `createSliderConstraint` ahora expande el rango por un
epsilon (1e-4 m) si `min == max`. Protege el test de F2H71 **y** el runtime del
editor. Detectado al correr la suite completa tras el Bloque B.
